### 2.2 Critical State File Schemas

**`data/seen_jobs.json`** – LinkedIn deduplication memory
```json
["4123456789", "4123456790", "4123456791"]
```
- **Type:** `string[]` (numeric job IDs as strings)
- **Loaded into:** `Set<string>` in `scraper.js:loadSeenJobIds()`
- **Growth:** ~500 IDs/day (DAILY_NEW_JOBS_LIMIT)
- **DynamoDB Schema:** Table `SeenJobs`, PK: `jobId` (S), TTL: 30d recommended

**`data/ats_sent_jobs_history.json`** – ATS deduplication memory
```json
{
  "lastUpdated": "2026-02-19T...",
  "totalCount": 1234,
  "sentJobIds": ["comeet_abc123", "greenhouse_456", "workday_nvidia_JR789"]
}
```
- **Type:** Object with `sentJobIds: string[]`
- **Loaded into:** `Set<string>` in `JobStateService`
- **DynamoDB Schema:** Table `AtsSentJobs`, PK: `jobId` (S), Attribute: `source` (S), TTL: 60d

**`data/companies_list.json`** – Company registry
```json
[
  { "id": "melio", "name": "Melio", "type": "comeet", "uid": "...", "token": "..." },
  { "id": "gong", "name": "Gong", "type": "greenhouse", "uid": "gong" }
]
```
- **DynamoDB Schema:** Table `Companies`, PK: `id` (S), Attributes: type, uid, token, enabled

### 3.2 Cloud Blockers

#### 🔴 CRITICAL: Lambda Timeout (15-min limit)

| Bottleneck | Estimated Duration | Impact |
|-----------|-------------------|--------|
| **LinkedIn scraper full run** | **30–90 minutes** | 🔴 **Far exceeds 15-min limit.** 16 queries × 4 pages × (3-7s page delay + 3-6s per job enrichment) + 10-20s query gaps + 120-180s batch cooldowns. |
| **Comeet WAF cooldown** | 2–5 min per 403/406 | 🔴 Single WAF block can consume >30% of Lambda timeout. Multiple blocks could cascade. |
| **ATS batch (all workers parallel)** | 5–20 minutes | 🟡 Depends on company count. Comeet (3-6s/co) + Greenhouse (6-12s/co) + Workday (5-6s/page × multiple pages). |
| **Workday session initialization** | 2s fixed + cookie establishment | 🟡 Minor but adds up across companies. |

**Recommendation:** Split LinkedIn scraper into per-query Lambda invocations triggered by EventBridge → SQS, each processing 1 query with 4 pages (estimated 2-5 min each). ATS workers can each be a separate Lambda.

#### 🔴 CRITICAL: Puppeteer / Headless Chrome Dependency

| Module | Puppeteer Usage | Lambda Impact |
|--------|----------------|---------------|
| `utils/ats_discover.js` | `puppeteer.launch()` for headless network interception | 🔴 ~400MB uncompressed. Exceeds Lambda 250MB deployment limit. Requires Lambda container image or Lambda Layer with `@sparticuz/chromium`. |
| `tools/comeet/harvest_comeet_puppeteer.js` | `puppeteer.launch()` for token scraping | 🔴 Same. Offline tool – **should NOT be deployed to Lambda.** |

**Recommendation:** Classify `tools/*` and `utils/ats_discover.js` as offline/dev-only. Strip `puppeteer` from production `package.json`. If ATS discovery is needed in cloud, use a separate Lambda container image.

#### 🔴 CRITICAL: `process.exit()` Calls

| File | Lines | Trigger | Impact |
|------|-------|---------|--------|
| `linkedin_client.js` | 115, 139 | Auth challenge (302/303 redirect) | 🔴 **Kills the Lambda container immediately.** No graceful shutdown, no state persistence. |
| `scraper.js` | 609 | Fatal error in standalone mode | 🟡 Only in `require.main === module` block. Orchestrator mode is safe. |

**Recommendation:** Replace `process.exit(1)` in `linkedin_client.js` with `throw new Error('CRITICAL_AUTH_FAIL')` – the orchestrator already catches this.

#### 🟡 MODERATE: In-Memory State Assumptions

| Pattern | File(s) | Issue |
|---------|---------|-------|
| **Singleton `JobStateService`** | `services/JobStateService.js:153` | `const jobStateService = new JobStateService()` – module-level singleton. In Lambda, this persists across warm invocations but resets on cold starts. |
| **`this.runStats` on worker instances** | `comeetWorker.js`, `greenhouseWorker.js`, `workdayWorker.js` | Run statistics accumulate in memory during a run. Lost if Lambda freezes or crashes. |
| **Comeet `RateLimiter` singleton** | `ats/utils/httpClientWrapper.js:10` | `rateLimiters.comeet` persists across warm Lambda invocations – could cause unexpected timing. |
| **WorkdayWorker session state** | `workdayWorker.js:153-168` | `CookieJar`, `_sessionInitialized`, `_locationFacet` cached per instance. New Lambda invocation = new session needed. |
| **LinkedIn `seenIds` Set** | `scraper.js:249` | Built from `seen_jobs.json` at start. In a distributed Lambda setup, parallel invocations could duplicate jobs. |

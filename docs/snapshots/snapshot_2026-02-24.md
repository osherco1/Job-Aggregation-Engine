## 3. Core Achievements (Technical)

### 3.1 Root Cause Analysis — Confirmed Hypotheses

| ID | Hypothesis | Verdict | Evidence |
|---|---|---|---|
| **H4** | MongoDB Atlas quota exceeded → ALL writes silently fail → `persistSentHistory` fails → bot "forgets" sent jobs | **CONFIRMED — PRIMARY ROOT CAUSE** | Terminal logs: `"you are over your space quota, using 520 MB of 512 MB"` on every write operation |
| **H3** | Non-deterministic Workday IDs (`unknown_${Date.now()}`) → same jobs get new IDs each run → dedup always fails for these | **CONFIRMED — SECONDARY** | Debug logs showed 5 NVIDIA jobs with `DATE_NOW_FALLBACK` IDs; `rawJob.title` contained `JR2005686` etc. |
| **H2** | `filteredJobsBuffer` module-level array not cleared between Cloud Run container reuse | **CONFIRMED — MINOR** | Code inspection proved the array was never reset in `run()` |
| **H1** | In-memory state leak across Cloud Run invocations | **SUPERSEDED** | Moot — H4 (quota) was the dominant failure mode |
| **H5** | `persistState` never reached due to `emailSuccess=false` | **SUPERSEDED** | Moot — H4 (quota) ensured writes would fail regardless |

### 3.2 Fix 1: Calibration DB Architecture (Replacing Bloated `run_logs`)

**What changed:** Completely redesigned the MongoDB data storage model from a single monolithic `run_logs` collection to purpose-built lightweight collections with TTL-based lifecycle management.

**Why:** The `run_logs` collection stored full raw API responses (`type: 'raw'`) and full normalized+raw dropped job payloads (`type: 'filtered'`), growing at ~15MB per run × 32 runs/day = **~480MB/day**. This exceeded the 512MB free tier within 24 hours, blocking ALL MongoDB writes (including the critical `ats_sent_history` dedup writes).

**Where in code:**

| File | Function/Section | Change |
|---|---|---|
| `services/storage/MongoStorageAdapter.js` → `this.collections` | Collection registry (L26-35) | Added `CALIBRATION_REJECTED`, `CALIBRATION_PASSED`, `RUN_SUMMARIES` |
| `services/storage/MongoStorageAdapter.js` → `_ensureTTLIndexes()` | New method (L272-297) | Creates TTL indexes on first connection: `calibration_rejected` = 60 days, `run_summaries` = 30 days |
| `services/storage/MongoStorageAdapter.js` → `writeRunLog()` | Production gate (L336) | Skips `type: 'raw'` and `type: 'runtime'` when `NODE_ENV=production`; routes `type: 'summary'` to `run_summaries` instead of `run_logs` |
| `services/storage/MongoStorageAdapter.js` → `_stripJobForCalibration()` | New helper | Strips `raw`, `description`, `normalized` — keeps only `{ jobId, title, companyName, location, url, reason, source }` |
| `services/storage/MongoStorageAdapter.js` → `writeCalibrationRejected()` | New method | Inserts stripped rejected jobs into `calibration_rejected` with `createdAt` (for TTL) |
| `services/storage/MongoStorageAdapter.js` → `writeCalibrationPassed()` | New method | Inserts stripped passed jobs into `calibration_passed` with `createdAt` |
| `services/storage/StorageAdapter.js` | Base class | Added no-op `writeCalibrationRejected()` and `writeCalibrationPassed()` defaults |

**Data stripping in workers (defense-in-depth):**

| File | Change |
|---|---|
| `ats/workers/comeetWorker.js` → all 3 `droppedJobs.push()` calls | Removed `raw: rawJob` and `normalized: normalized`; added `companyName`, `url`, `source` |
| `ats/workers/comeetWorker.js` → `saveDroppedJobs()` | Changed from `writeRunLog({type:'filtered'})` → `writeCalibrationRejected(droppedJobs)` |
| `ats/workers/greenhouseWorker.js` → all 3 `droppedJobs.push()` calls | Same stripping as Comeet |
| `ats/workers/greenhouseWorker.js` → `saveDroppedJobs()` | Same redirection as Comeet |
| `ats/orchestrator.js` → `persistResults()` | `filteredJobsBuffer` → `writeCalibrationRejected()`; removed `writeEnrichedJobs()` call |
| `ats/orchestrator.js` → Phase 5b | New: `writeCalibrationPassed(newJobs)` after email success + state persist |

**Impact/Risk:**
- The `run_logs` and `enriched_jobs` collections are no longer written to in production. They were manually dropped by the user from MongoDB Atlas.
- Calibration data retention is bounded by TTL: rejected jobs auto-expire after 60 days, run summaries after 30 days.
- No operational data loss — `seen_jobs`, `ats_sent_history`, and `companies` are untouched.
- Risk: If `NODE_ENV` is not set to `production` in a Cloud Run job, raw logs will still be written. This is mitigated by the Dockerfile having `ENV NODE_ENV=production`.

### 3.3 Fix 2: Fail-Fast Persistence

**What changed:** The `persistSentHistory()` method now **throws errors** instead of catching and silently logging them.

**Why:** The original code had a `try/catch` in `MongoStorageAdapter.persistSentHistory()` that caught `bulkWrite` failures and only logged them. This meant the orchestrator never knew the save failed, and would report `"✅ Job history updated"` even when no data was actually saved. Combined with H4 (quota exceeded), this created a silent feedback loop where dedup state was never persisted.

**Where in code:**

| File | Function | Change |
|---|---|---|
| `services/storage/MongoStorageAdapter.js` → `persistSentHistory()` catch block | L216-221 | Added `throw err;` after `console.error` |
| `services/JobStateService.js` → `persistState()` catch block | | Added `throw err;` to re-throw from `storageAdapter.persistSentHistory()`, propagating failure to orchestrator |

**Impact/Risk:**
- The orchestrator will now see persistence failures as exceptions, preventing false success reporting.
- If MongoDB is temporarily unavailable, the entire run will fail loudly rather than silently producing duplicate emails.

### 3.4 Fix 3: Deterministic Workday IDs

**What changed:** The `_normalizeJob()` function in `workdayWorker.js` now extracts JR requisition numbers from `rawJob.title` or `rawJob.bulletFields` before falling back to the non-deterministic `Date.now()`.

**Why:** 5 NVIDIA Workday jobs had no `externalPath`, causing the regex extraction to fail. The fallback generated `unknown_${Date.now()}` — a different ID every run. These jobs were **always** treated as "new" even if persistence worked correctly.

**Where in code:**

| File | Function | Change |
|---|---|---|
| `ats/workers/workdayWorker.js` → `_normalizeJob()` | Job ID extraction chain | Added: `const _titleStr = rawJob.title \|\| ''; const _bulletsStr = Array.isArray(rawJob.bulletFields) ? rawJob.bulletFields.join(' ') : ''; const _jrMatch = _titleStr.match(/(JR\d{4,})/) \|\| _bulletsStr.match(/(JR\d{4,})/);` — inserted as a fallback before `Date.now()` |

**ID extraction priority chain (updated):**
1. `rawJob.id` / `rawJob.jobId` / `rawJob.jobRequisitionId`
2. `externalPath` regex (`_(JR\d+)$` or `([A-Z0-9_-]+)$`)
3. `externalPath.replace(/[\/\s]/g, '_')`
4. **NEW:** JR number from `rawJob.title` or `rawJob.bulletFields` via `/(JR\d{4,})/`
5. `unknown_${Date.now()}` (last resort fallback)

**Impact/Risk:**
- The 5 problematic NVIDIA jobs will now be correctly identified across runs.
- Any Workday company embedding JR numbers in the title/bullets will benefit from stable IDs.
- If a job truly has no JR number anywhere, the `Date.now()` fallback still activates, but this is a rare edge case.

### 3.5 Fix 4: Cloud Run State Reset

**What changed:** `filteredJobsBuffer.length = 0;` added at the very beginning of the `run()` function.

**Why:** `filteredJobsBuffer` is declared at module level. In Cloud Run, containers can be reused across invocations. If the buffer wasn't cleared, stale filtered jobs from a previous run could contaminate the current run.

**Where in code:** `ats/orchestrator.js` → `run()` function, first line after `const errors = [];`.

**Impact/Risk:** Minimal. This is a defensive guard against Cloud Run container reuse. Even if the container is fresh, `.length = 0` on an empty array is a no-op.

## 4. Contextual Delta (vs. Previous Snapshot `snapshot_2026-02-23.md`)

### New Insights

| Area | Previous State (v6.0) | Current State (v6.1) |
|---|---|---|
| **MongoDB storage model** | Single `run_logs` collection for all log types; `enriched_jobs` for output | Purpose-built collections: `calibration_rejected` (TTL 60d), `calibration_passed` (permanent), `run_summaries` (TTL 30d). Legacy collections deprecated. |
| **Error handling on persist** | `persistSentHistory` caught errors silently | **Fail-fast**: errors thrown and propagated to orchestrator |
| **Workday job IDs** | Falls back to `Date.now()` when `externalPath` missing | Extracts JR number from title/bulletFields before `Date.now()` |
| **State management** | `filteredJobsBuffer` not reset between runs | Explicitly cleared at `run()` entry |
| **Data payload size** | Dropped jobs stored with full `raw` + `normalized` (10-40KB/job) | Stripped to lightweight metadata (~200-500 bytes/job) |
| **Cloud Scheduler** | `*/45 8-22 * * *` (triggers at :00 and :45, 15-min gap) | `*/30 8-22 * * *` (triggers at :00 and :30, consistent 30-min intervals) |
| **Storage quota risk** | ~480MB/day growth → quota hit in <24h | ~170MB steady-state with 60-day TTL (33% of quota) |

### Behavior Changes

- **No more `enriched_jobs` writes** — the `writeEnrichedJobs()` call was removed from `persistResults()` in `orchestrator.js`.
- **Summary logs are now time-limited** — `type: 'summary'` writes go to `run_summaries` (TTL 30d) instead of the permanent `run_logs`.
- **Workers send stripped payloads** — `comeetWorker.js` and `greenhouseWorker.js` no longer store `raw` or `normalized` objects in their dropped job arrays.
- **Calibration passed data** — a new "Phase 5b" in the orchestrator writes lightweight metadata for jobs that were emailed, enabling future analytics on pass rates.

### Reversed Decisions / New Constraints

- **`run_logs` collection still exists in code** (`this.collections.RUN_LOGS`) but is only written to in non-production environments. This was a deliberate choice to preserve local development debugging.
- **`enriched_jobs` collection still exists in code** but the write call was removed from the orchestrator. It could be re-enabled for analytics if needed.

### Known Failure Modes

| Failure Mode | Symptom | Diagnosis | Resolution |
|---|---|---|---|
| **MongoDB quota exceeded** | `"you are over your space quota"` errors in Cloud Logging; duplicate emails resume | Check Atlas storage usage → Collections tab | Drop `run_logs` / `enriched_jobs` if they exist; verify TTL indexes are active |
| **LinkedIn auth redirect** | `LinkedInAuthChallengeError` in errors; 0 LinkedIn jobs | Cookie expired | Rotate `LINKEDIN_LI_AT`, `JSESSIONID`, `CSRF_TOKEN` in Secret Manager |
| **Workday WAF block** | `403` or `0 jobs` from specific Workday companies | Workday anti-bot detection | Adjust `WORKDAY_DELAY_*_MS` env vars to increase delay |
| **Comeet rate limit** | `429` responses | API rate limit hit | Increase `COMEET_RATE_LIMIT_*_MS` env vars |
| **Persist failure** | Run crashes with `"Failed to persist sent history"` | Fail-fast throw from `persistSentHistory` | Check MongoDB connectivity and quota |
| **Container state leak** | Unlikely after Fix 4, but: stale data from previous run appearing | `filteredJobsBuffer` reset missing | Verify `filteredJobsBuffer.length = 0` at start of `run()` |

## 3. Core Achievements (Technical)

### 3.1 Two-Stage Deep Research Pipeline

- **What:** Replaced single-call `sonar` API pattern with a two-stage architecture: `sonar-deep-research` for discovery → `sonar-pro` for structured parsing.
- **Why:** Perplexity confirmed (via direct meta-prompting consultation) that enforcing `json_schema` on `sonar-deep-research` causes **early stopping** due to output token budget constraints (~8K-10K practical limit). The Web UI achieves 15+ companies because it uses segmented retrieval and iterative search loops. The two-stage approach decouples the research from the formatting.
- **Evidence of effectiveness:**
  - Single-stage `sonar` (original): **0 companies** for GH/WD, 9 for Comeet.
  - Single-stage `sonar-deep-research` + `json_schema`: **3–7 companies** per ATS.
  - **Two-stage** `sonar-deep-research` → `sonar-pro`: **15–19 companies** per ATS (48 total in best run).
- **Where:**
  - `perplexityClient.js` L17–23: model constants (`sonar-deep-research`, `sonar-pro`).
  - `perplexityClient.js` — `discoverCompaniesRaw()`: Stage 1 with `search_context_size: "high"`, `reasoning_effort: "high"`, no `response_format`.
  - `perplexityClient.js` — `parseCompaniesJson()`: Stage 2 with `RESPONSE_FORMAT` schema, includes critical instruction to extract actual ATS URLs (not generic homepages).

### 3.2 Schema Simplification (4-Field Universal Schema)

- **What:** Reduced the JSON schema from 5 fields (`company_name`, `ats_api_url`, `ats_identifier`, `careers_page_url`, `confidence`) to 4 fields (`company_name`, `careers_page_url`, `evidence`, `confidence`).
- **Why:** Removing `ats_api_url` and `ats_identifier` eliminates the primary source of LLM hallucination. The LLM no longer attempts to guess Comeet tokens, Greenhouse slugs, or Workday tenant IDs.
- **Where:** `perplexityClient.js` L32–57 — `RESPONSE_FORMAT` constant.

### 3.3 Static URL Extractor Module

- **What:** New deterministic module `tools/discovery/extractor.js` (76 lines) that classifies career page URLs via regex and extracts ATS-specific identifiers.
- **Why:** Tokens and identifiers are embedded in publicly visible URLs. Regex extraction is 100% reliable for Greenhouse (slug in URL path) and Workday (tenant.datacenter in domain). The LLM was failing at this task because it tried to infer values rather than parse them.
- **Extraction logic per ATS:**

| ATS | Regex | Extracts | Notes |
|-----|-------|----------|-------|
| Greenhouse | `/boards\.greenhouse\.io\/([a-z0-9_-]+)/i` | `{ uid: 'slug' }` | Also handles `boards-api.greenhouse.io` |
| Workday | `/([a-zA-Z0-9_-]+)\.(wd\d+)\.myworkdayjobs\.com/i` | `{ url: originalUrl }` | Passes original URL through (no truncation) |
| Comeet | `/comeet\.com\/jobs\//i` or `/comeet\.co\//i` | `{ careersUrl: url }` | Routes to CSV handoff |

- **Where:** `tools/discovery/extractor.js` L17–72.

### 3.4 Hard Deduplication (Code-Level)

- **What:** After the Stage 2 parser returns JSON, a code-level deduplication step filters out any company whose name (case-insensitive) already exists in the DB.
- **Why:** The `sonar-deep-research` model reads 100+ sources and occasionally "forgets" the exclusion list instructions, returning companies that are already in the database. This is a structural limitation of deep research agents.
- **Evidence:** In the best run, hard dedup dropped **9/19 Comeet candidates**, **1/9 Greenhouse candidates**, and **4/14 Workday candidates** that the LLM returned despite being in the exclusion list.
- **Where:** `run_discovery.js` — `processAts()`, after `parseCompaniesJson()` and before `filterByConfidence()`.

### 3.5 Comeet CSV Handoff & Fallback Routing

- **What:** Comeet leads are routed to a CSV file (`tools/comeet_list.csv`) instead of downstream validation, because Comeet token extraction requires Puppeteer (which cannot run in Cloud Run).
- **Fallback mechanism:** If the `classifyAndExtract()` returns `null` for a URL during the Comeet loop, the code forces the route to CSV anyway. This catches companies whose career pages don't contain `comeet.com` or `comeet.co` in the URL (e.g., `company.io/careers` with an embedded Comeet widget).
- **Where:** `run_discovery.js` — Comeet fallback logic after `classifyAndExtract()`.

### 3.6 Workday Extractor — URL Pass-Through

- **What:** The Workday extractor was iterated 3 times across the session:
  1. **v1:** Strict regex requiring path segments → rejected all URLs.
  2. **v2:** Forgiving regex + reconstructed `/en-US/External` suffix → HTTP 500 (Workday rejects unknown paths).
  3. **v3 (current):** Forgiving regex + **pass-through of original LLM URL** → first successful validations (PayPal 634 jobs, Tricentis 86 jobs).
- **Why:** Workday career sites have tenant-specific path segments (e.g., `/en-US/PTC`, `/crowdstrikecareers`, `/jobs`). Truncating or reconstructing these causes HTTP 500 Internal Server Errors. The LLM already provides the correct full URL.
- **Where:** `extractor.js` L59–63.

### 3.7 Dry Run Email Suppression

- **What:** Email report sending is now gated on `!DRY_RUN`.
- **Why:** During rapid Dry Run iteration, emails were spamming the user's inbox with every test run.
- **Where:** `run_discovery.js` — email section at end of pipeline.

### 3.8 Legacy Comeet Scripts Modernisation

- **What:** Three legacy Comeet scripts (`harvest_comeet_puppeteer.js`, `add_comeet_company.js`, `add_comeet_quick.js`) were refactored to use `MongoStorageAdapter.upsertCompany()` instead of local JSON file writes.
- **Why:** MongoDB is the single source of truth. The legacy scripts were writing to `data/comeet_companies_auto.json`, which is not synced to the cloud.
- **Where:** `tools/comeet/` — all 3 scripts, plus new `upsertCompany()` in `MongoStorageAdapter.js`.

### 6.2 Known Failure Modes & Diagnosis

- **Workday HTTP 500 on validation:** Some Workday tenants return 500 when the career site path is incorrect (e.g., `/en-US` without the tenant-specific suffix). Debug logging now prints the exact URL, status code, and first 500 chars of response body. Two error patterns observed:
  1. Generic "Error" page with red CSS header — indicates invalid path.
  2. Redirect to `community.workday.com/maintenance-page` — indicates Workday internal maintenance or WAF block.
- **Comeet "unconfirmed" mass drop:** When all Comeet candidates are flagged `unconfirmed` by Stage 2, zero leads reach CSV. This is a prompt/model issue, not a code bug. Mitigation: loosen confidence filter for Comeet, or accept `"likely"` as sufficient.
- **Perplexity 401 (API credits exhausted):** `sonar-deep-research` costs $0.50–$1.00 per call. Multiple rapid Dry Runs can exhaust a small API balance. Check billing dashboard at `https://labs.perplexity.ai`.
- **Hard dedup false positives:** Case-insensitive name matching may miss variants (e.g., "KLA" vs "KLA Corporation"). Current implementation is conservative.

## 4. Core Achievements (Technical)

*   **Lexical Editor Instant Injection**
    *   **What changed:** Replaced `page.keyboard.type` directed at a `<textarea>` with an instant `document.execCommand('insertText')` directly into `#ask-input[contenteditable="true"]`.
    *   **Why:** Perplexity relies on Meta's Lexical editor, rendering `keyboard.type` extremely slow and prone to errors. `execCommand` mimics a "paste" operation perfectly. A synthetic `input` event (`dispatchEvent`) was also added immediately afterward to force the underlying React DOM to register the injected text.
    *   **Where:** `tools/discovery/local_ui_discovery.js` (Prompt injection flow).

*   **Radix UI Deep Research Activation**
    *   **What changed:** Built `ensureDeepResearch(page)` logic utilizing exact ARIA selectors (`button[aria-label="Add files or tools"]`) to target the `+` menu. Once open, it scrapes menu options, reading `aria-checked` states before deciding to click "Deep research".
    *   **Why:** Perplexity removed the exposed "Pro" toggle and placed it within a floating Dialog. The standard interaction heuristics (like finding `.closest('form')`) completely broke.
    *   **Where:** `tools/discovery/local_ui_discovery.js` (`ensureDeepResearch` function).

*   **SPA Navigation Context Survival Loop**
    *   **What changed:** Replaced Puppeteer’s native `page.waitForFunction` with a custom Node.js `while(true)` polling loop enveloped in a silent `try...catch` block.
    *   **Why:** When the form is submitted, Perplexity uses Next.js routing to immediately transition from `/` to `/search/...`. This rips out the DOM execution context while Puppeteer is waiting, immediately crashing the script with a `Waiting failed` violation. By decoupling the wait check to the Node runtime, the script seamlessly ignores the navigation exception, waits 2000ms, and re-polls the new DOM.
    *   **Where:** `tools/discovery/local_ui_discovery.js` (`waitForGeneration` function).

*   **Disabled Infinite Generation Timeouts**
    *   **What changed:** Enforced `timeout: 0` during the generation observation phase.
    *   **Why:** Puppeteer halts scripts after 30,000 milliseconds, but Perplexity's Deep Research feature intrinsically requires 1-3 minutes of analysis and thought-processes.
    *   **Where:** `tools/discovery/local_ui_discovery.js` (Wait functions).

*   **Markdown Container DOM Selection Updates**
    *   **What changed:** Sunset `.prose.text-pretty` selectors, shifting strictly to `div[id^="markdown-content-"]` targeting `pre.not-prose code` or `pre code` specifically filtering for JSON elements utilizing `[data-testid="code-language-indicator"]`.
    *   **Why:** Major unannounced UI updates by Perplexity deprecated previous styling classes used to find the final Markdown containers.
    *   **Where:** `tools/discovery/local_ui_discovery.js` (Extraction snippet inside the main ATS iteration).

## 5. Contextual Delta (vs Previous Snapshot)

**Changes since Baseline (`snapshot_2026-03-06.md`):**
*   **Discovery Automation Mechanism:** Previously we leaned heavily on single-call LLM interactions (like direct `sonar` queries without UI scraping). Today's realization explicitly proved that to exploit "Deep Research", we *must* interface with Perplexity's local GUI via Headless browser logic if we want to bypass the API restrictions.
*   **React SPA Knowledge:** We definitively learned that native Puppeteer `page` handlers are profoundly unsafe against modern Next.js SPAs because of `Execution Context Recreated` events. Decoupling verification into the native Node.js Event Loop is now the requisite pattern.
*   **Perplexity Selectors:** We have abandoned generic `menu` or `.prose` class expectations in favor of strictly deterministic identifiers: ARIA paths, Test-IDs, and dynamic `^=` Regex-like ID selectors.

## 6. Configuration Snapshot

Current core variables acting as the ultimate sources of truth:

*   **`DAILY_NEW_JOBS_LIMIT` (LinkedIn Limit)**
    *   **Value:** `500`
    *   **Source:** `scraper.js` (Line 84).
    *   **Behavior:** Forces the LinkedIn scraper to cease iterations outright to prevent overwhelming downstream handlers (Mailer & Storage bottlenecks).
*   **`JITTER` (Delay/Cooldown Values)**
    *   **Value:** Dynamic usage of `randomDelay(minMs, maxMs)`. 
    *   **Source:** `scraper.js` (Line 166). 
    *   **Behavior:** Defines critical spacing intervals between LinkedIn fetches to prevent 429 Bot Triggers. E.g., `(10000, 20000)` between boolean queries, `(3000, 6000)` between detailed job calls, and large cool-downs `(120000, 180000)` spanning multi-minute rests across batches.
*   **`BLACKLIST_KEYWORDS` & `WHITELIST_KEYWORDS`**
    *   **Value:** Broad arrays excluding terms like 'Senior', 'Manager', 'Financial', 'HR', non-tech 'Physics'.
    *   **Source:** `filters_shared.js` (Lines 12-190).
    *   **Behavior:** First filters jobs dropping any match to a Blacklisted string. Subsequently, mandates at least *one* exact match against Whitelisted elements ('Software', 'Developer', 'DevOps', 'QA').
